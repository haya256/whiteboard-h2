# 画像 / Miro から openboard のボードを再現する

入力は2経路。どちらも最終的に「仕様 JSON → `scripts/board-from-spec.js` → .svg」の流れで生成する。

| 経路 | 入力 | 精度 | 仕様 JSON の作り方 |
|---|---|---|---|
| A. 画像 | `.jpg` / `.png` | 目視のため中 | 自分で画像を読み取って書く（下記「手順」） |
| B. Miro | ボード URL / ID | 高（座標・色・コネクタ・ラベルをデータで取得） | `scripts/miro-to-spec.js` が自動生成 |

出力: 経路 A は `<画像名>_edited.svg`（画像と同じフォルダ）、経路 B は `data/<ボード名>_edited.svg`。アプリの「開く (.svg)」で読め、ブラウザで直接開いても同じ見た目になる。

Miro のアーカイブ（.rtb）は本体が暗号化されているため入力にできない。PDF は未対応（必要なら pdfjs 追加で経路を増やせる）。

## 経路 B: Miro のボードを取り込む

前提: `config/miro.json`（git 管理外）に `{ "token": "..." }`（boards:read 権限のアクセストークン）がある。無ければユーザーに配置を依頼する（トークンをチャットに貼らないよう伝える）。

```bash
node scripts/miro-to-spec.js <ボードURL または ボードID> <spec.json の保存先> [--dump <生JSONの保存先>]
node scripts/board-from-spec.js <spec.json>
```

- ボード一覧は `GET https://api.miro.com/v2/boards` で確認できる（トークンのチーム内のボードのみ）。目的のボードが見つからなければ、そのボードをトークンのアカウント / チームに共有してもらう。
- 変換の対応: 付箋（色はパレット5色に対応付け、文字サイズは付箋に収まる最大の段階を自動選択、正方形か 3:2 に丸める）、図形（塗り・枠線・文字）、テキスト、フレーム（薄い枠として再現）、コネクタ（矢印の向き・線種・色・太さ・ラベル）。同じ2要素間の複数コネクタは1本にまとめる。画像・埋め込み・カード等はスキップして警告に出す。
- 仕様 JSON は自動生成後に手で直せる（経路 A と同じ形式）。座標は Miro の値を左上原点に平行移動したもの。
- 出力の警告（未対応要素・まとめたコネクタ）を報告に含める。

## 経路 A: 画像を読み取る

生成は `scripts/board-from-spec.js`（リポジトリ同梱）が行う。自分の仕事は **画像を読み取って仕様 JSON を書くこと** と、結果の検証・報告。

## 手順

### 1. 画像を見る

- `Read` ツールで画像ファイルを開いて内容を目視する（画像は視覚的に提示される）。
- `node scripts/board-from-spec.js --dims <画像>` でピクセルサイズを取得する。座標はすべて **画像のピクセル座標**（左上原点）で書く。
- 読み取るもの:
  - 付箋・ボックス: 文字、色（黄 / ピンク / 水色 / 緑 / 紫 のどれに近いか）、中心位置、大きさ、文字の相対的な大きさ
  - 独立したテキスト（背景なし）
  - 線・矢印: どのノードからどのノードへ、矢印の向き（なし / 終点 / 始点 / 両端）、直線か曲線かカギ線か、色（黒系 / 灰色 / その他）、線に添えられたラベル
- 小さい文字や手書きは読み間違えやすい。自信のないものは報告時に明示する。

### 2. 仕様 JSON を書く

スクラッチパッドに `<画像名>.spec.json` を書く。`image` は仕様ファイルからの相対パスか絶対パス。

```json
{
  "image": "/abs/path/図.jpg",
  "title": "図",
  "includeImage": true,
  "nodes": [
    { "name": "A", "type": "sticky", "content": "エー", "cx": 190, "cy": 135, "size": 180, "fontSize": 40, "bg": "yellow" },
    { "name": "B", "type": "sticky", "content": "ビー\n2行目", "cx": 578, "cy": 335, "size": 116, "fontSize": 22, "bg": "pink" },
    { "name": "C", "type": "shape", "shape": "ellipse", "content": "シー", "cx": 300, "cy": 500, "w": 160, "h": 120, "fontSize": 24 },
    { "name": "memo", "type": "text", "content": "補足", "cx": 700, "cy": 100, "fontSize": 18, "color": "#757575" }
  ],
  "edges": [
    { "from": "B", "to": "A", "arrow": "end", "label": "仲良し" },
    { "from": "B", "to": "C", "arrow": "both", "label": ["秘書", "社長"] },
    { "from": "C", "to": "A", "arrow": "end", "line": "curved", "color": "#757575", "label": { "text": "殺害", "offset": [20, 0] } }
  ]
}
```

フィールド:

- 共通: `name`（コネクタから参照する識別名。省略時は `content`）、`content`（改行は `\n`）、`cx` / `cy`（中心、画像px）、`fontSize`（px。省略時 32）、`color`（文字色）、`bold`、`align`（left/center/right）、`valign`（top/middle/bottom）、`link`（URL）
- `sticky`: `size`（正方形）または `w` / `h`（3:2 なら w:h = 3:2 にする）、`bg`（`yellow` / `pink` / `blue` / `green` / `purple` か `#hex`。省略時 yellow）
- `shape`: `shape`（rect / ellipse / diamond）、`w` / `h`、`bg`（省略時 白）、`border`（省略時 #4a90e2）
- `text`: `w` / `h` は省略可（文字数から自動）
- `edges[]`: `from` / `to`（name）、`arrow`（none / end / start / both。省略時 end）、`line`（straight / curved / elbow。省略時 straight）、`color`（省略時 #333333）、`width`（省略時 2）、`label`（文字列、文字列の配列、または `{ text, offset:[dx,dy], fontSize, color }`。線の中点付近にテキストノードとして置かれる。配列の1つ目は線の上側、2つ目は下側にずれる）
- 全体: `includeImage`（省略時 true。元画像を再現図の右隣に埋め込んで見比べられるようにする。1.5MB 超は自動で省略）、`scale`（画像px→ワールド倍率。省略時 1）、`output`（出力先を変えたいとき）、`viewport`

### 3. アプリの制約に合わせる（重要）

- **同じ2ノード間にコネクタは1本だけ**。画像で往復の2本や並行する2本がある場合は、両端矢印（`both`）の1本にまとめ、`label` を配列で2つ置く。
- **アンカーは自動**（左右または上下の中央）。線の経路は指定できないので、他の付箋を突き抜けてしまう線は省いて報告に書く。曲線（`curved`）は端点から外向きに膨らむ。
- **付箋は正方形か 3:2** にする（アプリの UI がその2択のため）。
- **文字をはみ出させない**。付箋の内側は左右 12px・上下 10px の余白、行高 1.55。目安: 1行の文字数 × fontSize ≤ size − 24。収まらなければ `size` を上げるか `fontSize` を下げる。スクリプトが推定して警告を出すので、警告が出たら直して再実行する。
  - 目安表: 3文字 → size 80 / fontSize 18、4文字 → 116 / 22、2行×4文字 → 116 / 20、6文字1行 → 180 / 40（2行に折り返す）
- コネクタのラベルはアプリに機能がないので、テキストノードで代用する（スクリプトが自動配置）。
- 色は付箋パレットの5色に寄せる。画像の色が薄いピンクでもパレットの `pink` を使う。

### 4. 生成する

```bash
node scripts/board-from-spec.js <spec.json>
```

出力にノード数・コネクタ数・警告が出る。警告（はみ出し、重複コネクタ、端点不明）があれば仕様を直して再実行する。スクリプトは `<metadata>` を読み戻して検証するので、「端点の無いコネクタ」が 0 であることを確認する。

### 5. 報告する

- 出力パス、ノード数・コネクタ数
- 確認方法: アプリの「開く (.svg)」、またはテストサーバー起動中なら `http://localhost:8080/data/<ファイル名>` でブラウザ表示
- 判断した点を箇条書きで: まとめたコネクタ、省いた線、読み取りに自信のない文字、文字サイズの調整
- 微調整はアプリ上で行う前提であることと、仕様を直して再生成できることを伝える

## 注意

- 生成ファイルは `data/` など git 管理外の場所に置く（`data/` は .gitignore 済み）。仕様 JSON はスクラッチパッドに置く。
- ブラウザ描画はこの環境では確認できない。配置の最終確認はユーザーに依頼する。
- スクリプトはアプリの `src/io.js` の書き出し用 CSS と `src/model.js` / `src/view.js` のアンカー・経路計算を写しているので、アプリ側でそれらを変えたらスクリプトも合わせる。
- `config/miro.json` のトークンは読み取り専用でも秘密情報。ログや報告に出さない。
